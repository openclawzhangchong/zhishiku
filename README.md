## 这是什么

一位中职教师 + AI 助手，在一年多里并行推进了这些事：

**第一批（01–14，45 个项目 / 66.7 万字符日志）**

- 📱 小乐 AI 语音助手（Flutter 客户端 v1.0.0 → v7.6.x + 单文件网页版 + Cloudflare Worker 后端）
- 📖 《信息技术基础》学考课件、1227 题题库、辅导书、在线组卷系统
- 🎮 纯代码绘制的 HTML5 玛力欧风格游戏（无外部资源）
- 🔧 MCP 服务器接入、阿里云运维、班主任材料审核工作台、课堂点名系统

**第二批（15–24，2 个项目 / 约 25 万字符日志 + 大量工程文档）**

- 💬 自建 AI 聊天产品（Cloudflare Pages + D1，10 天 38 个版本，29 个测试套件 + 50 条变异测试）
- 🖥️ Windows 桌面 UI 自动化（微信朋友圈自动点赞 v1.0.0 → v2.5.0，纯像素识别 + PyInstaller 打包）
- 📦 安卓 Capacitor 外壳与云端打包（三份副本、六个烧掉的 CI）
- 🎙️ 语音输入 STT / 朗读 TTS 全链路

**这些项目的每一次翻车与每一次成功，都被 AI 写进了工作日志。本库就是从全部日志 + 大量 PLAN / CHANGELOG / 故障报告 / HANDOFF 交接件 / 协议文档中，交叉归并、去重、重组的产物。**

## 怎么用

**开工前** — 扫一遍 `14_铁律速查 · 100条（第一批）.md`（100 条，A–I 九类）和 `24_铁律速查 · 80条（第二批）.md`（80 条，A–H 八类），多数低级错误能提前拦掉。

**遇到故障** — 按上表定位主题篇，看「踩坑清单」的四列：【现象】【根因】【修复】【可复用规则】。

**做新东西** — 找对应篇的「成功配方 / 具体实现」章节，里面是可照抄的清单（配色表、字号表、架构分层、脚本模板、命令）。

**让 AI 用** — 把 `00_总索引 · 症状速查导航.md` 或具体主题篇投喂给你的 AI 助手，它能在开工前就知道这个环境里哪些坑不能踩。

## 贯穿全库的 12 条顶层原则

1. **先方案、后动手** — 改动前出 PLAN md，批准后才改代码。
2. **证据优于猜测** — 任何诊断必须带文件:行号、日志时间线、对照实验数据。
3. **回滚锚点常在** — 动手前打锚点 tag，失败过的 tag 永不复用。
4. **单一真相** — 一仓一种推送通道，一份文档一个真相源，改了必回填。
5. **绝不说失败是成功** — CI 红灯如实标记，严禁长期挂"待验证"。
6. **改共用东西前先查谁在用** — 共用回调、公共变量是事故高发区。
7. **状态位必须 finally 复位** — 忙标志、开关、连接标记，异常路径也要复位。
8. **验证跑完整链路** — 只复制两个函数做验证 = 漏掉加载期崩溃。
9. **确定性验证优于随机冒烟** — 精确注入状态 + 真实 `update()` 才能命中窄分支。
10. **批量授权、一次问清** — 一次解决 5–7 个决策点，别中途反复打断。
11. **大改动分批** — 先做一份验收，通过后再推全量。
12. **经验立刻 Skill 化** — 踩过的坑当天写进技能文件，否则下次必重踩。

**第二批追加 5 条**：

13. **只读诊断** — 诊断时不许动代码，报告写明"只读、未改任何代码"和诊断时点。
14. **副本必有守门** — 同一文件两个以上副本，必须有一条自动检查一致的测试。
15. **测试要被验证** — 判断测试有没有用，唯一方法是故意改坏看它红不红（变异测试）。
16. **不确定的技术点先建测试站** — 一次性最小项目跑通再动主工程，把争论变成数字。
17. **"做不到"要警惕** — 那往往只说明你想到的那条路走不通，换种元素再来一次。
